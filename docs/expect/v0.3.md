# Expectation: v0.3

> In short: one release with four parts. `nook eng pull` brings a Jira ticket into the backlog through Teamwork Graph. An area installs its dependencies when they are missing. `nook view` shows a desk in the browser, and the owner decides at the gates there. `nook search` finds words across the wiki, the items and the courses.

The release is done when each scenario passes on a real desk, and `bun run check` passes.
The plan of the release names the slices, the dependencies with their versions, and the order. The owner approves the plan before code.

## Part 1: the tracker

The `engineering` section of `nook.yml`:

```yaml
engineering:
  tracker: { type: jira, site: company.atlassian.net }
```

`nook eng pull <KEY...>` reads each ticket with `twg jira workitem get <KEY> --full -o json` and its files with `twg jira workitem attachment`.
It writes `backlog/<KEY>/ticket.md` and `backlog/<KEY>/attachments/`, then makes or updates the item.

| # | Given | When | Then |
|---|---|---|---|
| T1 | `tracker: jira` and a `twg` login | the owner types `/intake SHOP-12` | `ticket.md` holds Fields, Description, Acceptance criteria and Comments as Jira holds them; item `SHOP-12` is in `backlog` with the browse link as its source |
| T2 | a ticket with two files of 10 MB or less | the pull runs | both files are in `attachments/`; a larger file shows as a link in `ticket.md` |
| T3 | an item that is pulled already | the ticket changed in Jira and the pull runs again | `ticket.md` holds the new text; the item keeps its state; the report names each section that changed |
| T4 | no `twg` on the path, or no login | the pull runs | it exits 3 with the fix, such as `twg login`; `nook doctor` shows the same gap |
| T5 | a pulled ticket | the scout reads it at intake | it reports each sentence that reads as an instruction, as today |
| T6 | any desk | an agent reads `~/.config/twg/auth.conf` | the secret guard blocks it |
| T7 | any pull | it runs | it reads only: Nook never creates, edits, moves or comments on a Jira ticket |
| T8 | a desk | an agent runs a write command of `twg`, such as `twg jira workitem update` | the guard blocks it; `twg jira workitem get` passes |

## Part 2: the area install

| # | Given | When | Then |
|---|---|---|---|
| I1 | an area with `install: bun install` and no `node_modules` | `nook eng item verify` runs | the install runs first, then the checks; the run records the install |
| I2 | an installed area whose lockfile changed after the last install | `item verify` or `task prove` runs | the install runs again before the checks or the proof |
| I3 | an installed area with no change of its lockfile | `item verify` runs | no install runs |
| I4 | an install that fails | `item verify` runs | no check runs; the result names the install and its first error lines |
| I5 | an area with no `install` | `item verify` runs | no install runs, as today |

A lockfile is one of `bun.lock`, `package-lock.json`, `pnpm-lock.yaml`, `yarn.lock`, `uv.lock`, `poetry.lock`, `Gemfile.lock`, `go.sum` and `Cargo.lock`.

## Part 3: the viewer

`nook view` in a desk starts the server and opens the browser. Ctrl-C stops it. The first start builds the app.

| # | Given | When | Then |
|---|---|---|---|
| V1 | a desk | the owner runs `nook view` | the server listens on `127.0.0.1` at the port of this desk, and the browser opens with a one-time token |
| V2 | the browser has the token | it opens the first page | the token becomes an HttpOnly, SameSite=strict cookie; a second use of the token fails |
| V3 | the home page | the owner opens it | it shows the parts of `nook brief`: what waits, what is done, what runs, and each gap of `nook doctor` |
| V4 | items in four states | the owner opens `/work` | one column for each state that holds items; each card shows the id, kind, size, title and criteria |
| V5 | an item in planning | the owner opens `/work/SHOP-12` | the tabs Spec, Plan and Tasks show the documents with Bench diagrams; the guesses and the open questions show beside them |
| V6 | the page of the item | the owner clicks approve | the server runs `nook eng item approve SHOP-12`; the ledger records `owner (viewer)`; a refused move shows its gaps and fixes |
| V7 | the page is open | an agent changes `plan.md` or a slice | the page shows the change within 2 seconds, with no reload |
| V8 | the wiki | the owner opens `/wiki` | the shelves, each index, and each page with its links; the drafts that wait for a yes |
| V9 | a course | the owner opens `/learn` | the cards due, the top patterns of the mistakes, and the scores of each criterion over time |
| V10 | the viewer runs | an agent calls its port from Bash | the hook blocks the call |
| V11 | the viewer runs | a page reads the desk | it never reads a secret file |
| V12 | the read modules | they run under Node | no read path uses a Bun API; the ledger opens through one SQLite interface for Bun and for Node |
| V13 | the owner types `/view SHOP-12` | the companion answers | it gives the link of the item in the viewer, and builds no HTML file |
| V14 | the owner asks to share the page of `SHOP-12` | the export runs | one HTML file holds the page with its styles inline, and opens from the disk with no server |
| V15 | a second start, with no change of the Nook code | the owner runs `nook view` | the server starts with no build |

When the export covers a page, its old builder goes in the same release: `nook eng item page`, `nook eng doc page` and `scripts/pages/`.

## Part 4: the search

| # | Given | When | Then |
|---|---|---|---|
| S1 | wiki pages, item documents and course files | `nook search "payment retry"` runs | it lists each match with its file, its heading and a line of context, the best match first |
| S2 | the viewer is open | the owner types words in the search box | the same matches show, each one a link to its page in the viewer |
| S3 | a page changed after the last search | the next search runs | the index holds the new text first |
| S4 | no `.nook/search.db` | a search runs | Nook builds the index from the files, then answers |
| S5 | a secret file in the desk | the index builds | the secret file is not read and not indexed |

- `docs/report.md` states the build with its numbers, and `bun run pages` builds both pages again.
- Each Markdown file passes `nook ste`.
